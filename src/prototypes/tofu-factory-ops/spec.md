# 卢凡豆业订货配货结算系统原型

## 📋 业务与功能

### 1.1 核心目标

本原型用于豆腐工厂的日常订货、配货、复秤、交付留痕与结算管理，目标是把目前依赖微信消息、人工记忆、纸面整理和照片散落的流程，收敛成一套可追溯、可结算、适合家庭工厂使用的轻量业务系统。

核心用户包括：

- **管理者**：维护商品、商户、价格、结算日、账单与经营数据，主要使用管理端。
- **配货人员/家人**：每天早上查看订货清单，完成称重、拍照、送货确认，主要使用移动端。
- **B 端商户**：超市、小商贩等固定客户，可查看自己的订单、供货记录、结算单，主要使用移动端/H5。
- **散户/零售客户**：可记录临时订单与零售流水，作为非固定商户的轻量录入对象。

本阶段只产出规格文档，待用户确认后再生成 `index.tsx` 原型实现。

### 1.2 业务痛点

- **订货信息分散**：B 端客户通过微信下单，需要人工翻聊天记录、记忆和整理每天早上的供货清单。
- **配货过程不可追溯**：配货前复秤、配货照片、实际出货重量和供货完成记录目前没有统一归档。
- **价格规则复杂**：不同商户有不同结算单价，且存在三类常用供货配置与自定义价格。
- **结算依赖人工**：需要按商户结算日汇总供货记录，手动计算金额、生成账单、打印或发给商户。
- **移动场景强**：配货、复秤、拍照、送货确认都发生在现场，不能只做桌面后台。
- **家庭成员协同**：管理者、配货人员、商户看到的信息和可操作范围不同，需要角色区分。

### 1.3 功能清单

#### P0 必做功能

- **管理端首页工作台**：查看今日订单、待配货、待复秤、待送达、待结算、异常订单等关键状态。
- **商户管理**：录入商户名称、类型、地址、联系方式、结算单价、结算日、默认供货配置、备注。
- **商品与价格管理**：维护豆腐、黑豆腐、豆干、脆皮豆腐等商品，记录计价单位、默认单价、规格、是否称重、是否参与结算。
- **三类供货配置**：预设三种常用供货配置，并允许按商户自定义商品组合、结算单价和结算日。
- **筐管理**：记录每个商户当前占用筐数、每次送出筐数、回收筐数、应回收筐数和差异，类似水站桶管理；不收押金，主要用于防丢和提醒回收。
- **订货录入**：支持后台代录微信订单、粘贴微信文本和截图 OCR 辅助整理订单，移动端也可快速补录订单。
- **今日供货清单**：按日期、商户、商品汇总待配货数量和重量，形成早晨配货任务列表。
- **配货复秤记录**：配货前录入或确认实际重量，记录称重时间、操作人、差异值。
- **配货照片留存**：第一版强制留存复秤照片，订单支持单张或多张照片，配货成品照和送达照作为后续扩展。
- **供货完成记录**：记录送达状态、完成时间、签收/确认方式、异常备注。
- **结算单生成**：按商户、结算周期和结算日汇总供货记录，自动计算应收金额。
- **结算单打印/PDF**：生成可打印或导出的结算单，支持发给商户确认。
- **移动端配货模式**：给配货人员使用，聚焦“今日任务 → 复秤 → 拍照 → 完成”。
- **移动端商户视图**：给 B 端商户查看订单、供货记录、结算单和联系方式。

#### P1 建议补充功能

- **微信订单整理辅助**：预留“从微信粘贴文本识别订单”的入口，先做半自动解析，后期可接 OCR/AI 识别。
- **异常处理**：缺货、临时改量、未送达、商户拒收、重量差异过大等异常标记。
- **临时零售流水**：散户零售不走账期结算，默认当日收款、当日完成，可快速记录商品、重量、金额、支付方式。
- **收款状态**：结算单支持未收款、部分收款、已收款、逾期四类状态，并记录微信、支付宝、对公转账等付款方式。
- **账期提醒**：到结算日前自动提醒管理者生成或核对账单。
- **历史价格追踪**：商户价格调整后保留历史价格，避免历史结算被新价格覆盖。
- **操作日志**：关键动作记录操作人和时间，特别是订单、价格、结算、筐数量修改，便于家庭成员之间对账。

#### P2 后续可扩展功能

- **库存/产量记录**：记录每日生产量、剩余量、损耗量。
- **路线规划**：按地址和配送顺序生成送货路线。
- **商户小程序自助下单**：让固定商户直接提交明日订货。
- **数据报表**：按商户、商品、日期统计销量、毛收入、结算金额。
- **打印小票/标签**：配货时生成商户标签或配送单。
- **电子签收**：商户在移动端确认收货或签名。

### 1.4 交互要点

- **今日任务筛选**：选择日期或点击“今日待配货” → 更新任务列表、汇总重量和商户数量。
- **商户新增/编辑**：点击新增商户 → 打开表单 → 保存后进入商户详情，并可继续配置价格。
- **供货配置切换**：选择预设配置 → 自动带出商品组合与单价；选择自定义 → 允许逐项修改。
- **订单录入**：首页提供数据录入入口，支持手动录入、粘贴微信文本和截图 OCR 识别；选择商户 → 添加商品明细 → 输入数量/重量 → 保存为待配货订单。
- **复秤确认**：在移动端点击任务 → 输入实际重量或确认称重值 → 系统计算差异并标记复秤完成。
- **拍照留存**：点击拍照/上传 → 第一版至少留存复秤照片，图片附加到配货任务，任务状态进入“待送达”或“已配货”。
- **完成供货**：点击完成 → 记录完成时间、操作人、可选备注；若有异常可通过异常记录保存原因与补充说明。
- **筐交接记录**：完成供货时同步记录本次送出几个筐、回收几个筐、商户当前还占用几个筐；若应回收但未回收，需要标记为待回收，后续在商户详情和今日任务中提醒。
- **生成结算单**：选择商户与账期 → 系统汇总供货记录 → 生成结算明细与总额。
- **打印/PDF**：点击导出 → 生成面向商户的结算单版式，支持打印或 PDF。
- **商户查看账单**：商户端进入结算单 → 查看明细、金额、周期、付款状态。

### 2.2 页面范围

#### 交付顺序约束

本项目后续生成原型与开发时必须遵守以下顺序：

1. **第一阶段先做移动端**：优先完成配货人员移动端 H5，包括数据录入、OCR 识别、今日任务、任务详情、复秤、拍照、异常记录、完成供货。
2. **第二阶段再做管理端**：在移动端主流程确认可用后，再生成管理端商户配置、价格配置、结算和报表。
3. **商户端暂缓重投入**：当前版本不强制商户改变订货方式，商户端只保留低成本查看能力，例如结算单链接、PDF、供货记录查看。
4. **原型评审顺序**：先评审“老卢早上怎么用手机完成配货”，再评审“你如何在后台配置与结算”。

#### 移动端页面（第一阶段优先）

1. **配货人员首页**
   - 未登录时先显示登录卡片，没有注册入口，只允许使用后台手动配置的账号密码登录；默认示例账号为 `13333563336 / 123456`，默认登录用户为“老卢”。
   - 登录后底部导航固定为：首页、任务、基础管理。
   - 页面主体使用固定视口高度容器，内容区独立滚动，确保底部导航在首屏始终可见，不依赖先滚动到底部。
   - 登录后不保留独立顶部栏，页面内容直接从主功能区开始，避免再占一行高度。
   - 首页首屏直接展示数据录入入口，不再保留顶部统计横幅。
   - 首页默认选中并展开 `OCR 识别`，同时保留粘贴订单、手动补录入口。
   - 首页去掉 `新增商户`、`新增商品` 两个管理快捷入口，改为展示今日任务、待配送重量、待回收筐、待补照片 4 个业务指标。
   - 首页去掉“下一单”卡片，不再承载完整待处理任务队列。

2. **任务页**
   - 顶部先提供 `当日送货 / 全部列表` 双切换。
   - 增加任务搜索，支持按商户、地址、商品关键字过滤。
   - `待配送 / 已完成` 采用当日统计卡片样式展示，点击卡片后进入对应的当日送货队列。
   - 列表模式展示与图 3 一致的任务卡列表，保留 `全部 / 待复秤 / 待拍照 / 待送达 / 异常 / 已完成` 筛选。
   - 当日送货卡片展示商户、到达时间、应配重量、照片数和当前任务状态，适合司机按顺序点进下一单。
   - 全部列表任务卡展示商户、地址、应配/实秤重量、占用筐数、照片数和商品摘要。
   - 点击任务卡进入详情，详情页不占用底部 Tab。

3. **配货任务详情**
   - 商户地址、联系电话、商品明细、应配数量/重量。
   - 复秤输入、照片上传、筐交接编辑、异常备注、完成按钮。
   - 重点优化单手操作、大字号数字、明确单位和防误触确认。

4. **复秤与拍照页**
   - 先录入实际重量，再拍照留存。
   - 若实际重量与应配重量差异超过阈值，提示填写原因。
   - 支持多张照片：称重照片、配货成品照片、送达照片可按阶段扩展。

5. **筐交接编辑**
   - 展示交接前占用筐数。
   - 本次送出、本次回收使用可编辑步进器录入。
   - 系统实时计算交接后占用筐数，并在完成供货时同步保存。

6. **异常记录**
   - 缺货、临时改量、商户拒收、未送达、重量差异等场景快速选择。
   - 支持手动输入补充说明，非必填；必要时可继续补充照片。

7. **基础管理页**
   - 顶部为简洁的双标签切换：`商户` / `商品`，无额外说明文字。
   - 商户页支持按商户名称、电话、地址、结算日搜索；商户列表每行显示商户名称、类型、待结算金额、欠筐数、结算日；点击商户跳转到独立的商户详情页。
   - 商户详情页展示商户档案（类型、电话、地址、结算日、优惠倍率、欠筐数）以及配货历史；配货历史每条记录可点击展开详情，展示商品明细、实秤重量、送/收筐数、配货照片和操作人信息。
   - `新增商户` 做成按钮，点击后跳转到独立的新增商户表单页面，填写完毕保存后自动返回商户列表。
   - 结算日支持三种周期：每日结算、每周（选择星期几）、每月（选择几号）。
   - 商品页展示商品列表（含规格标签），点击某个商品跳转到商品详情页，可查看规格列表并新增规格；`新增商品` 做成按钮，点击后跳转到独立的新增商品表单页面。
   - 优惠倍率作为后续金额计算口径保留在商户档案中。

#### 管理端页面（第二阶段）

1. **管理端工作台**
   - 今日订单数、今日预估供货重量、待复秤、待完成、待结算、异常数量。
   - 今日供货清单预览，按商户排序。
   - 结算日提醒，例如“明天需结算 3 家商户”。

2. **商户管理页**
   - 表格字段：商户名称、商户类型、联系人、电话、地址、默认配置、结算日、状态。
   - 操作：新增、编辑、停用、查看供货记录、生成结算。

3. **商户详情与价格配置页**
   - 基础信息：名称、类型、地址、联系方式、备注。
   - 价格配置：三类预设配置、自定义商品单价、结算日。
   - 历史供货：最近订单、最近结算单。

4. **订单与今日供货页**
   - 支持从微信信息手动录入或粘贴订单文本。
   - 自动汇总为今日供货清单。
   - 显示订单状态：待配货、待复秤、已配货、已送达、异常。

5. **配货复秤与照片记录页**
   - 展示每个商户的配货任务。
   - 记录应配重量、实际重量、差异、复秤人、复秤时间、照片。
   - 支持查看照片证据和完成记录。

6. **结算管理页**
   - 按商户和账期生成结算单。
   - 明细字段：日期、商品、订单数量、实际重量、单价、小计、照片凭证、备注。
   - 支持 PDF/打印、标记收款、记录收款方式。

### 2.3 数据来源

- **数据类型**：商户表
- **数据源**：生成示例数据；后续建议新增 `src/database/tofu-merchants.json`
- **关键字段**：
  - `id`: 商户 ID
  - `merchant_name`: 商户名称
  - `merchant_type`: 商户类型（超市/小商贩/散户/其他）
  - `contact_name`: 联系人
  - `phone`: 联系方式
  - `address`: 地址
  - `settlement_day`: 结算日，例如每月 5 日、每周日、日结
  - `discount_rate`: 优惠倍率，例如 1、0.95
  - `pending_amount`: 当前待结算金额
  - `settled_amount`: 累计已结算金额
  - `default_supply_config`: 默认供货配置
  - `current_basket_count`: 当前商户占用筐数
  - `basket_warning_count`: 待回收或长期未回收筐数
  - `delivery_history`: 最近配货/结算记录
  - `status`: 启用/停用
  - `remark`: 备注

- **数据类型**：筐交接记录表
- **数据源**：生成示例数据；后续建议新增 `src/database/tofu-basket-records.json`
- **关键字段**：
  - `id`: 筐交接记录 ID
  - `merchant_id`: 商户 ID
  - `order_id`: 关联供货任务 ID
  - `delivery_date`: 供货日期
  - `sent_basket_count`: 本次送出筐数
  - `returned_basket_count`: 本次回收筐数
  - `before_balance`: 交接前商户占用筐数
  - `after_balance`: 交接后商户占用筐数
  - `pending_return_count`: 当前待回收筐数
  - `operator`: 记录人
  - `remark`: 备注，例如商户说明下次归还

- **数据类型**：商品表
- **数据源**：生成示例数据；后续建议新增 `src/database/tofu-products.json`
- **关键字段**：
  - `id`: 商品 ID
  - `product_name`: 商品名称，限定为豆腐、黑豆腐、豆干、脆皮豆腐
  - `unit`: 计量单位，第一版默认使用斤；如部分商品按块/板配送，可在备注中记录换算口径
  - `default_price`: 默认单价
  - `price_options`: 可选单价列表，用于豆腐这类存在 2 元/斤、2.5 元/斤两档价格的商品
  - `need_weight`: 是否需要复秤
  - `status`: 上架/停用

- **数据类型**：商户价格配置表
- **数据源**：生成示例数据；后续建议新增 `src/database/tofu-price-configs.json`
- **关键字段**：
  - `id`: 配置 ID
  - `merchant_id`: 商户 ID

### 2.5 已确认业务规则

以下规则已根据你的补充确认，后续原型与开发必须按这些口径执行：

1. **结算周期**：每个商户都可自定义结算周期和结算日。
2. **称重单位**：第一版统一以斤为主，同时在录入和展示层支持筐、板与斤/公斤的换算备注。
3. **商品与价格**：固定商品包括豆腐、黑豆腐、豆干、脆皮豆腐；豆腐支持 2 元/斤、2.5 元/斤两档价，黑豆腐 4 元/斤，豆干分调味 6 元/斤和未调味 5 元/斤两个规格，脆皮豆腐 6 元/斤。
4. **商户下单方式**：第一版不要求商户自助下单，继续沿用微信下单；内部通过微信代录、粘贴文本或截图 OCR 辅助整理订单，降低商户学习成本。
5. **配货照片**：订单可支持单张或多张照片，但第一版只强制要求复秤照片，其他配货成品照、送达照作为后续扩展。
6. **付款方式**：收款记录需要支持微信、支付宝、对公转账。
7. **价格变更规则**：价格变更立即生效，但历史订单和已生成结算单应保留当时成交单价，避免历史账单被新价格覆盖。
8. **家庭成员权限**：老卢可以查看配货任务，也可以修改订单和价格；原型中不做过重权限限制，但关键修改应保留操作日志。
9. **散户零售结算**：散户零售不走账期结算，默认当日收款、当日完成，只沉淀流水记录。
10. **打印格式**：结算单需要显示工厂抬头、联系方式、签字栏和商户确认栏。
11. **手动补录规则**：移动端手动补录必须支持从全部商户中选择商户，并按商品、规格、数量、重量逐行选择录入。
12. **优惠倍率规则**：商户档案中必须维护优惠倍率，后续待结算金额与手动补录预估金额统一按该倍率计算。
13. **移动端基础管理范围**：移动端需要支持现场新增商户、查看商户配货历史，并维护商品规格与价格。

### 2.6 端形态建议：H5 优先，小程序后置

结合你已有自己的域名和服务器，以及四五线城市小商贩、商超人员的信息化接受度，当前版本建议采用：

**第一版：移动端 H5 优先，不强制商户使用系统。**

原因：

- **上线成本低**：H5 可以直接部署在你的域名和服务器上，不需要小程序审核、备案类额外流程或平台能力适配。
- **分享成本低**：结算单、供货记录可以直接通过微信发链接，商户点开就能看，不需要先搜索/授权/学习小程序。
- **迭代速度快**：业务流程还在打磨阶段，H5 修改和发布更快，适合先验证“配货复秤留痕 + 结算”这个核心闭环。
- **内部使用更合适**：第一阶段主要给老卢和家里人用，H5 可以直接固定到微信收藏、手机桌面或浏览器书签。
- **保留升级空间**：等流程稳定、商户愿意查看账单或自助下单后，再把同一套移动端能力封装成微信小程序。

不建议第一版直接重投入小程序的原因：

- 商户未必愿意主动学习新入口；如果他们仍然习惯微信发消息，下单强行迁移会增加阻力。
- 小程序更适合“商户主动下单、查看账单、确认收货”这些商户侧动作，但当前最痛的是你们内部整理、配货、复秤和结算。
- 如果第一版就让商户改操作逻辑，容易出现“系统做好了但商户不用”的风险。

推荐阶段策略：

1. **阶段 1：内部移动端 H5**
   - 商户继续微信下单。
   - 你或家人把微信订单录入/粘贴到系统。
   - 老卢用 H5 完成今日配货、复秤、拍照、完成供货。
   - 你在后台或后续管理端生成结算单。

2. **阶段 2：商户轻量 H5 查看**
   - 商户不需要注册复杂账号。
   - 通过微信收到结算单链接或 PDF。
   - 点开后只看“本期供货明细、金额、付款状态、联系方式”。

3. **阶段 3：小程序化**
   - 当固定商户愿意线上看账或自助报订货时，再做小程序。
   - 小程序重点承载：商户自助下单、历史供货、结算单确认、电子签收。

### 2.7 商户低学习成本策略

第一版原则：**不改变商户原有微信订货习惯，只改变工厂内部的整理、配货、复秤和结算方式。**

具体策略：

- **商户继续微信发订单**：不要求商户下载、不要求注册、不要求每天进入系统下单。
- **内部代录为主**：你们收到微信订单后，由管理者或家人录入系统，系统负责汇总供货清单。
- **商户只被动接收结果**：结算单、供货明细、PDF 通过微信发给商户即可。
- **商户端只做“看”不做“填”**：第一版商户最多查看账单、供货记录和联系方式，不承担复杂操作。
- **减少账号体系负担**：商户查看结算单可使用一次性链接、手机号校验或简化口令，不做复杂登录流程。
- **保留人工兜底**：商户不会用链接时，仍可直接接收 PDF 图片或打印纸质单，不影响业务。
- **用系统服务内部效率**：核心价值先落在你们自己少记错、少漏单、少扯皮、结算清楚，而不是一开始要求所有商户配合。

## 🎨 布局与结构

### 3.1 整体布局

本原型采用“一套业务模型，两类端”的结构，但原型生成顺序必须是移动端优先：

- **移动端**：第一阶段主入口，采用 H5 形态优先，适合老卢现场配货、复秤、拍照、完成供货；商户侧只做轻量查看，不强制改变微信订货习惯。
- **管理端**：第二阶段桌面中后台，适合你进行商户配置、价格维护、结算、报表查看。

#### 管理端布局

- **布局模式**：左侧导航 + 顶部状态栏 + 主内容区。
- **容器宽度**：流式布局，适配 1280px 以上桌面屏。
- **信息密度**：中高密度，表格、筛选器、状态标签和汇总卡片并重。
- **关键尺寸**：
  - 侧边导航：展开约 220px。
  - 顶部栏：约 64px，高亮当前日期与快捷操作。
  - 工作台指标区：4-6 个核心指标，桌面端横向排列。
  - 表格区：占据主视觉，支持横向滚动和固定操作列。
  - 详情/编辑：复杂表单优先使用右侧抽屉或独立详情区。

#### 移动端布局

- **布局模式**：H5 全屏单列作业台 + 任务流 + 吸底 Tabbar，优先适配 375px-430px 手机宽度。
- **登录前结构**：顶部保留紧凑工厂栏，正文展示登录卡片；没有注册入口，只允许使用后台配置账号密码登录。
- **首页结构**：首屏先展示今日任务、待配送重量、待回收筐、待补照片 4 个业务指标卡片，下方为”新增订单”标题和三种数据录入入口（OCR 识别、粘贴订单、手动补录），不再保留”下一单”卡片。
- **任务页结构**：顶部先切换“送货视图 / 列表视图”，并提供任务搜索；送货视图继续切换“待配送 / 已完成”，用紧凑队列卡片服务顺路配送；列表视图使用横向状态筛选 + 商户任务卡，卡片内突出地址、重量、筐数、照片数和商品标签，减少现场查找成本。
- **基础管理结构**：采用 `商户 / 商品` 双模块切换，商户列表每行显示欠筐数量，点击进入商户档案与配货历史；新增商户和新增商品均跳转独立表单页面。
- **详情页结构**：进入任务后隐藏 Tabbar，顶部展示商户和路线信息，正文按“复秤记录 → 复秤照片 → 筐交接 → 商品明细 → 异常记录”分段，底部保留确认完成供货按钮。
- **信息密度**：低到中密度，优先展示下一步动作，不堆叠复杂表格。
- **触控尺寸**：核心操作按钮不低于 44px，高频按钮使用图标 + 短文字，适合单手操作。

### 3.2 响应式适配

- **桌面端（≥1200px）**：管理端使用完整导航、表格、筛选、右侧详情抽屉；移动端原型居中展示为手机壳宽度。
- **平板端（768-1199px）**：移动端原型扩展为双列/三列卡片布局，提高评审效率，同时保留底部导航。
- **移动端（<768px）**：进入完整 H5 全屏体验，取消外层圆角和阴影，Tabbar 固定吸底并适配安全区。

### 3.3 原型实现建议

确认后仍使用综合原型目录：`src/prototypes/tofu-factory-ops/`，但实现与评审顺序调整为：

1. `移动端配货首页`
2. `移动端任务详情`
3. `移动端复秤拍照`
4. `移动端完成供货/异常记录`
5. `商户端轻量账单查看`
6. `管理端工作台`
7. `商户与价格配置`
8. `订单/供货清单`
9. `结算单打印预览`

第一轮原型只需要把 1-5 做清楚；管理端相关页面放到第二轮，避免一开始被复杂后台分散重点。

这样可以先验证最关键的现场业务链路：早上配货人员是否真的能用手机完成“看任务、复秤、拍照、完成记录”。

## 🎨 视觉规范

### 4.1 设计规范来源

**设计规范来源**：`主题 /src/themes/antd-new`

**补充设计指导**：

- 管理端以 Ant Design 企业级中后台规范为主，强调清晰、稳定、高效率。
- 移动端参考 `frontend-design` 与 `taste-skill` 的高级前端体验要求，但控制动效，不做花哨视觉。
- 不使用默认 AI 紫蓝渐变风格；整体应贴近“清晨配货、账目清楚、家庭工厂可信赖”的务实气质。

### 4.2 自定义设计要点

#### 视觉方向

- **关键词**：清晨、豆制品、新鲜、秤重、账本、可靠。
- **推荐气质**：浅色、干净、带一点温润食材感，但仍然是工具型系统。
- **主色建议**：以 Ant Design 蓝色体系为基础，辅以低饱和豆绿色或米白背景作为局部氛围色。
- **数字风格**：重量、金额、单价使用更醒目的等宽或数字强调样式，降低看错风险。

#### 管理端视觉

- 使用清晰状态标签区分：待配货、待复秤、已配货、已送达、异常、已结算。
- 结算金额、实际重量、差异值需要高可读性。
- 表格操作按钮保持克制，不堆叠过多主按钮。
- 异常信息使用警告色，但不要大面积红色造成压力。

#### 移动端视觉

- 任务卡片主按钮突出下一步动作，例如“去复秤”“拍照留存”“确认送达”。
- 输入重量时字号要大，单位清晰，避免现场误输入。
- 拍照区域要明确展示已上传数量和缩略图。
- 完成操作需要二次确认，避免误点。

### 4.3 组件状态

- **默认态（default）**：白底、浅边框、清晰标题，信息按商户与任务分组。
- **悬停态（hover）**：管理端表格行、按钮、卡片产生轻微高亮。
- **聚焦态（focus）**：输入框、筛选器、复秤输入需要明显聚焦边框。
- **选中态（selected）**：当前商户、当前结算周期、当前任务高亮。
- **禁用态（disabled）**：已结算记录、停用商户、不可编辑价格置灰并显示原因。
- **加载态（loading）**：工作台指标、任务列表、结算生成使用骨架屏或按钮 loading。
- **空状态（empty）**：无今日订单时显示“今天还没有录入订货，可从微信消息代录”。
- **错误态（error）**：重量为空、单价缺失、照片未上传、结算周期无记录时给出明确原因。
- **异常态（warning）**：实际重量与应配重量差异超过阈值、商户账期逾期、订单未完成但进入结算。

本原型主要用于业务流程评审，暂不强制对接 Axure API；如后续需要导出或被其他原型调用，可预留以下事件与变量。

### 5.1 事件列表（eventList）

| 事件名称 | Payload 类型 | 触发时机 | 说明 |
|---------|-------------|---------|------|
| `on_order_created` | `Order` | 新增订单保存成功 | 返回订单与商户信息 |
| `on_weight_confirmed` | `WeighingRecord` | 完成复秤 | 返回实际重量、差异、操作人 |
| `on_basket_recorded` | `BasketRecord` | 完成筐交接记录 | 返回送出筐数、回收筐数、当前占用筐数 |
| `on_delivery_completed` | `DeliveryRecord` | 确认供货完成 | 返回完成时间、照片、备注 |
| `on_settlement_generated` | `Settlement` | 生成结算单 | 返回结算单 ID 与金额 |
| `on_merchant_selected` | `Merchant` | 选择商户 | 用于联动详情与价格配置 |

### 5.2 动作列表（actionList）

| 动作名称 | Params 类型 | 参数说明 | 功能描述 |
|---------|------------|---------|---------|
| `create_order` | `OrderInput` | 商户、商品明细、日期 | 创建订货记录 |
| `confirm_weight` | `WeighingInput` | 订单 ID、实际重量、操作人 | 写入复秤记录 |
| `record_basket_exchange` | `BasketInput` | 订单 ID、送出筐数、回收筐数 | 写入商户筐交接记录并更新占用筐数 |
| `upload_delivery_photo` | `PhotoInput` | 订单 ID、图片地址 | 绑定配货或送达照片 |
| `complete_delivery` | `DeliveryInput` | 订单 ID、完成时间、备注 | 标记供货完成 |
| `generate_settlement` | `SettlementInput` | 商户 ID、账期 | 生成结算单 |
| `mark_payment_status` | `PaymentInput` | 结算单 ID、收款金额、方式 | 更新收款状态 |

### 5.3 变量列表（varList）

| 变量名称 | 类型 | 默认值 | 说明 |
|---------|-----|-------|------|
| `selected_date` | `string` | 当日日期 | 当前查看的供货日期 |
| `selected_merchant_id` | `string` | 空 | 当前选中的商户 |
| `active_terminal` | `string` | `admin` | 当前展示端：管理端/配货移动端/商户端 |
| `current_order_status` | `string` | `all` | 当前订单状态筛选 |
| `settlement_period` | `object` | 当前账期 | 结算周期范围 |
| `pending_photo_count` | `number` | `0` | 待补照片任务数量 |
| `pending_basket_count` | `number` | `0` | 待回收或需提醒的筐数量 |
| `current_basket_merchant_id` | `string` | 空 | 当前正在记录筐交接的商户 |

**命名规范**：使用 snake_case（小写字母、数字、下划线）
